Self-Improving SQL Generation Agentic Harness

One system, built incrementally through all 13 modules. The project starts as a crude NL→SQL baseline and ends as a typed, verified, durable, eval-driven harness with a champion/challenger improvement loop.

Self-improving does not mean self-modifying in production. The harness observes benchmark failures, proposes configuration changes, evaluates challengers offline, and promotes only through explicit correctness, safety, cost, and approval gates.

Definition of done

  • The harness is model-agnostic and adapter-agnostic.
  • Unsafe SQL never reaches execution.
  • Correctness is evaluated against results, not merely SQL-string similarity.
  • Every settled numeric claim can be traced to evidence.
  • Loops are bounded and failures are explicit.
  • A challenger cannot become champion by improving average quality while regressing safety/hard correctness.
  • Every promoted configuration is versioned and reversible.
