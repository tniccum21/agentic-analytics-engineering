# Course labs

Early modules use **Northstar Retail**, a tiny bundled SQLite database with known answers. This keeps assignments deterministic and lets the tests grade architecture rather than enterprise-data access.

- Module 1 and 2 include executable starters and supplied acceptance tests.
- Modules 3–12 include precise assignment specifications. Add code beside each `assignment.md` as you reach the module.
- Module 4 introduces the course-supplied Northstar MCP server; Module 7 proves that the same Northstar workflow works through direct SQLite and MCP adapters.

The site tracks the same acceptance tests as checkboxes. Mark them only after the test or artifact demonstrates the behavior.


## Study-plan convention

The interactive course site presents exactly one **Study Plan** per module. That section consolidates required reading, required code study, study prompts, and optional paid enrichment. Assignment files may state the evidence to capture from those sources, but they should not introduce a second independent reading list.

The Study Plan appears **before** module lessons, comprehension checks, worksheets, and programming tasks. The expected sequence is: study first, then apply.

All required labs operate on course-supplied Northstar assets. A learner is never expected to arrive with an existing analytics platform, MCP server, or agent workflow.
